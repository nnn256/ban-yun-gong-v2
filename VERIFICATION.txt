2.0.7 self-message forwarding and hidden background launch — 2026-11-18 Asia/Shanghai

Fixes:
- Enable reportSelfMessage only on the owned SnowLuma WebSocket node, while every route include_self remains false unless explicitly enabled. Existing external nodes, login data and rules are retained. Upgrading this node requires connector restart.
- Resolve the verified peer for QQ self-sent private messages before route matching, deduplication and forwarding-receipt filtering. Missing peers do not route into the logged-in account's own session.
- Native EXE defaults to hidden background with NoBrowser/SkipDesktopActions. Windows login startup uses the native launcher and preserves manual-stop preferences through ResumeBackground. Background failures log and exit without a modal dialog.
- Recover owned Windows AstrBot launcher trees after a collector exit by verifying the recorded identity, exact launcher path and descendant working directory.
- Installer shortcuts offer hidden background and explicit workbench opening separately.
- Background VBS starts without a command window; CMD entries hand off and exit. The separate open-workbench VBS explicitly enables browser/login setup. Service and watchdog recovery/logging continue independently.

Verification:
- Real C# compilation and launcher behavior checks cover background/open/resume modes, no visible PowerShell console, detached VBS/CMD entry, failures without blocking dialogs and single-instance behavior.
- Plugin regressions cover self-message toggles on/off, group/private paths, QQ peer variants, unknown-peer rejection, duplicate events and bridge receipts. Feishu private self-message filtering is included.
- Upgrade regressions cover changing only the owned WS node and preserving rules/default-off state.
- package.ps1 runs the full unittest suite and Python/JavaScript/PowerShell syntax checks before sealing the release. The exact final output is retained alongside the deliverable.

Limits:
No real platform message has been sent during this continuation. Live self-message delivery still requires an online authenticated QQ/Feishu session. Hidden launch applies to program/service consoles and browser launch; platform QR/relogin UI may appear when required by the platform. Display-off operation is supported; sleep, hibernate, sign-out, shutdown and network loss interrupt forwarding. CMD may flash while handing off; VBS/native EXE avoids creating a CMD window.
